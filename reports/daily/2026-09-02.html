摘要: Qwen 发布 Qwen3.8-Max-0902，拥有 2.4 万亿参数和 100 万上下文 token，针对 Coding 与 Cowork 进行了后训练，面向复杂企业任务、科学研究和长时工作流。其 API 价格为每百万 token 输入 2 美元、输出 6 美元。模型在 Code Arena WebDev 排名第一，得分 1691，并在多步推理、工具使用、完整应用生成和数据分析等场景展现优势。

2. Claude Fable 5.1 与 Mythos 5.1 发布：编码和长任务升级

  • 来源: Claude (Twitter)
  • 分类: 模型发布
  • 重要性: ⭐⭐⭐⭐⭐ (5/5)
  • 标签: Claude Fable 5.1 Claude Mythos 5.1 代理编码 长时任务 Terminal-Bench 提示缓存 模型安全

摘要: Claude Fable 5.1 与 Claude Mythos 5.1 面向编码和知识工作发布，强调更强的代理编码、复杂长时任务与科学研究能力。Fable 5.1 在 Terminal-Bench 4.0 得分 55.8%，高于 Fable 5 的 42.0%，并在低推理强度下以更低成本保持竞争力。API 缓存读取价格降至每百万 token 0.25 美元，典型工作负载成本预计下降约 25%，高度代理化工作负载最多下降 45%；模型已接入 Claude Code 和 Claude Platform。安全方面，网络安全良性请求误报减少约 60%，企业前沿安全防护将分阶段推出，Messages API 也收紧了思维块前上下文编辑限制。 Anthropic表示，Fable 5.1擅长处理复杂且持续时间较长的任务。其研究能力也被描述为展示了AI模型参与科学进展的早期可能性。 Fable 5.1在Terminal-Bench-Science 0.1上的成绩为52.6%，超过Fable 5两倍以上。在Terminal-Bench 4.0上，它得分55.8%，高于Fable 5的42.0%。 Anthropic表示，Fable 5.1的性能显著高于Fable 5。将推理强度调低后，它仍能以更低成本达到相近或更好的结果。 Fable 5.1的缓存读取成本比Fable 5低75%。按该说法，典型工作负载的实际模型成本可下降约25%，高度代理化的工作负载最多可下降45%。 Anthropic推出企业前沿安全防护（EFS），在保持零数据保留级别隐私的同时，继续防范对抗性使用。该功能将从今年秋季开始分阶段推出。 Claude 表示已改进安全防护：网络安全防护对良性请求的误报减少约 60%，基础生物学和医学问题的 fallback rate 近期降低约 85%。 Claude Fable 5.1 已面向所有用户上线，面向网络防御者和生命科学家的 Claude Mythos 5.1 则通过可信访问计划提供。

4. Gemini 引入代理式视频理解，长视频最多省 88% token

  • 来源: GoogleDeepMind
  • 分类: 产品与功能
  • 重要性: ⭐⭐⭐⭐ (4/5)
  • 标签: Gemini 代理式视频理解 长视频 token 优化 Google AI Studio

摘要: Gemini 新增代理式视频理解能力，综合转录、音频和画面进行推理，并动态调整帧率来提取真正需要的片段，而非扫描整个文件。官方称该方法在提高分析准确率的同时最多减少 88% 的 token 使用量，对十分钟教程到数小时录制内容的长视频尤其有价值。能力正通过 API 在 Google AI Studio 中向 Gemini 3.7 Flash、3.6 Flash 和 3.5 Flash-Lite 推出，并将进入 Gemini App。 Gemini 现在会综合视频转录、音频和画面进行推理，并动态调整帧率以提取所需片段，而不是扫描整个文件。该能力对从 10 分钟教程到数小时录制内容的长视频效率提升最明显，正通过 API 在 Google AI Studio 中向 Gemini 3.7 Flash、3.6 Flash 和 3.5 Flash-Lite 推出，并将很快进入 Gemini App。

实践建议

  • 选取长教程或会议录像做基线测试，比较全量扫描与代理式抽帧的 token、延迟和关键信息召回率。
  • 把视频分析任务拆成检索、定位和总结三步，检查动态取样是否遗漏低频但关键的画面。

5. Meta 发布 Muse Voice Transcribe 实时语音模型

  • 来源: AIatMeta
  • 分类: 模型发布
  • 重要性: ⭐⭐⭐⭐ (4/5)
  • 标签: Muse Voice Transcribe 实时语音识别 声纹分离 多语言 自适应延迟

摘要: Muse Voice Transcribe 支持实时流式自动语音识别、超过 20 位说话人的声纹分离和端点检测，并支持多语言无缝切换。模型以自适应延迟逐块决定继续监听还是输出文本，在难词上等待更久、易词上更快提交，以平衡准确率和延迟。官方称其在流式语音转文字和公开声纹分离基准上排名第一，现已通过 Meta Model API、Mac 版 Meta AI 和 Muse Code 提供。 Muse Voice Transcribe 是 Muse Spark 系列的自回归多模态大语言模型，以每 80 毫秒一个 token 的方式处理音频，并逐块决定继续监听还是输出文本。模型通过结合词错误率和延迟奖励的强化学习实现自适应延迟，在难词上等待更久、易词上更快提交，从而逐词权衡准确率与延迟。 Meta 表示，Muse Voice Transcribe 通过自适应延迟，在以最终转写耗时衡量的速度与准确率权衡中达到了帕累托前沿。该结果强调了模型在实时转写中对延迟和准确率的平衡能力。 Muse Voice Transcribe 现已通过 Meta Model API、Mac 版 Meta AI 和 Muse Code 提供。该消息同时附上了进一步了解产品的链接。

实践建议

  • 用包含多人对话、口音和中英切换的真实音频测试流式转写，分别记录延迟、词错误率和说话人分离准确率。
  • 在实时应用中比较固定延迟与自适应延迟策略，按用户可接受的首字和最终结果延迟设定阈值。
