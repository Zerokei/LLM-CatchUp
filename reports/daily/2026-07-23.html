1. OpenAI 推出 ChatGPT Health：连接医疗记录与 Apple Health

  • 来源: OpenAI Blog
  • 分类: 产品与功能
  • 重要性: ⭐⭐⭐⭐⭐ (5/5)
  • 标签: ChatGPT 健康AI 医疗数据 隐私安全 Apple Health

摘要: ChatGPT Health 开始向美国 18 岁以上登录用户推出，用户可在许可后连接 Apple Health、支持的医疗记录、One Medical 和 Function Health，让模型结合用药、化验、就诊、睡眠和活动等信息回答健康问题。功能提供逐次授权、断开后删除同步数据、额外加密和不用于训练或广告等保护，但 OpenAI 强调它不能替代专业医疗判断。

实践建议

  • 在测试健康类 AI 功能时只连接必要数据，并逐项检查授权范围。
  • 把模型输出当作就医准备和信息整理辅助，重要医疗决定需与专业人员核实。

  • 分类: 模型发布

摘要: Qwen 发布 Qwen-Image-3.0，定位为新一代基础图像生成模型，重点提升复杂文字、知识表达和多层嵌套界面的生成能力。示例覆盖报纸、分镜和复杂 UI 等生产场景，显示模型正在从通用画面生成走向结构化内容制作。相关线程进一步展示了语义排版和细节控制能力。

📎 多角度报道:

  • 对生成内容增加文字校对和版权审核，避免把视觉输出直接当作最终发布素材。

3. Claude Managed Agents：努力级别、技能规模与会话控制升级

  • 来源: Claude Devs (Twitter)
  • 分类: 产品与功能
  • 重要性: ⭐⭐⭐⭐ (4/5)
  • 标签: Managed Agents 代理技能 努力级别 会话控制

摘要: Claude Managed Agents 新增努力级别、会话控制和更多代理配置能力，并支持单个会话最多添加 500 个技能。开发者可以用技能为代理提供任务专属指令，再通过 cookbook 和发布说明接入这些能力。更新同时扩大了长时间运行代理的可配置范围和复用能力。

📎 多角度报道:

  • Claude Managed Agents 单会话最多支持 500 个技能 · Claude Devs (Twitter) · 技能规模与配置

实践建议

  • 先为高频任务建立小型技能集合，逐步评估 500 技能上限下的检索、冲突和维护成本。
  • 为代理努力级别和会话控制设置明确的超时、预算和人工接管策略。

5. Claude 接入 Anthropic Economic Index：对话查询 AI 经济活动数据

  • 来源: Claude (Twitter)
  • 分类: 研究
  • 重要性: ⭐⭐⭐⭐ (4/5)
  • 标签: Anthropic Economic Index 数据连接器 AI 经济 研究数据

摘要: Claude 现在可以直接查询 Anthropic Economic Index，这是用于衡量 AI 使用与经济活动变化的公开数据集。用户可以在对话中探索数据和相关指标，连接器则通过 Anthropic 的目录进行启用。该功能把公开研究数据从静态报告转化为可交互分析入口。 Anthropic 为 Claude 推出 Economic Index 连接器，用户可以直接查询 AI 在不同行业、职业和任务中的实际使用数据。连接器让研究人员、记者和政策制定者无需离开对话即可探索指数，同时完整数据集仍可免费下载。

6. OpenAI Presence：企业语音与聊天智能体上线

  • 来源: OpenAI (Twitter)
  • 分类: 产品与功能
  • 重要性: ⭐⭐⭐⭐ (4/5)
  • 标签: OpenAI Presence 企业智能体 语音代理 护栏与评测 Codex

摘要: OpenAI 推出 Presence，帮助企业部署能够回答问题、调用内部系统、执行获批操作并在必要时转交人工的语音和聊天智能体。产品把策略、护栏、标准流程、模拟评测和受控发布结合起来，并通过 Codex 分析生产会话和升级记录提出改进。Presence 已向符合条件的企业限量开放，部署由 OpenAI 前置工程师和系统集成商参与，尚非自助式产品。

实践建议

  • 先选定一个高价值流程，明确代理可执行动作、审批点和人工升级条件。
  • 上线前用边界案例和模拟评测验证策略，发布后持续分析升级记录并对变更做受控回归。

10. OpenAI API 向全账户开放硬性消费上限

  • 来源: OpenAI Devs (Twitter)
  • 分类: 产品与功能
  • 重要性: ⭐⭐⭐ (3/5)
  • 标签: OpenAI API 消费上限 成本控制 用量监控

摘要: OpenAI API 开始向所有账户扩大硬性消费上限的访问范围，团队可以在平台中设置预算边界并降低意外超支风险。控制台同时提供用量和消费查看入口，方便开发者持续监控 API 成本。该更新把费用治理从企业专属能力扩展到更广泛的 API 用户。 OpenAI Devs 提醒用户前往 API 平台控制台查看当前用量和消费情况。该信息与硬性消费上限配套，帮助开发者在预算耗尽前发现异常调用或成本增长。

实践建议

  • 为开发、测试和生产项目分别设置硬性消费上限，并配合用量告警做分级处置。
  • 定期核对控制台用量与业务指标，及时发现异常调用或失控重试。
